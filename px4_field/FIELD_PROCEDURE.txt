  실외 데이터 수집 절차 — F1 / F2 / F3
  AUW = 1.326 kg   운용 고도 2.0 m   (2026-08-03)
════════════════════════════════════════════════════════════════════════

목적: UKF 모델 계수를 실기체에서 확보한다.
  F1 호버   → C_thrust, 결합항 k_norm, 자이로 σ, GPS 속도 σ
  F2 doublet → G = C_torque / I      (축별)
  F3 직선왕복 → drag_x, drag_y

핵심 순서 의존: F1 을 먼저 뜨고, 거기서 나온 "호버 스로틀"을
                F2 의 --thrust 에 넣어야 한다. 순서를 바꾸지 말 것.

[0]  가져갈 것
────────────────────────────────────────────────────────────────────────
  □ 기체 + 프로펠러 (장착 확인, 손상·밸런스 점검)
  □ 배터리 3개 이상 (만충)
  □ 조종기  ← 모든 비행에서 안전 오버라이드로 필수
  □ 노트북 (QGC 설치됨) + USB 케이블   ← F1 로그를 현장에서 봐야 함
  □ 젯슨 SSH 접속 가능한 상태 (핫스팟/공유기)
  □ 종이·폰 메모   ← 로그 파일명 ↔ 비행 매칭용
  □ 안전조종사

  조건: 바람 약한 시간대 (F1 이 특히 민감)
        F3 용으로 기수 방향 10 m + 오른쪽 10 m 트인 공간


────────────────────────────────────────────────────────────────────────
[1]  현장 도착 후 (비행 전)
────────────────────────────────────────────────────────────────────────
  1-1. 기체 전원 ON, GPS 3D 고정 대기
       QGC 에서 위성 수 / eph 확인.  eph 2 m 이하가 바람직.
       (실내 테스트 때 eph 34 m 였던 건 GPS 불량 상태였음)

  1-2. 젯슨 SSH 접속
         cd ~/px4_field
         ls                        # f1_hover.py f2_doublet.py f3_drag.py 확인

  1-3. 토픽 살아있는지 1회 확인
         ros2 topic echo /fmu/out/vehicle_status --qos-reliability best_effort --once

  1-4. 조종기로 시험 이륙 → 고도 2.0 m 유지 가능한지 확인 → 착륙

  ※ 저고도(2.0 m) 운용 기준으로 세팅돼 있다.
     세 스크립트 모두 진입 최소고도가 1.5 m 이므로 2.0 m 면 통과한다.
     지면효과는 0.5 m 이하에서나 나오므로 2.0 m 는 계수 측정에 문제없다.


────────────────────────────────────────────────────────────────────────
[2]  F1 — 정지 호버 120초
────────────────────────────────────────────────────────────────────────
  [SSH]
      cd ~/px4_field
      python3 f1_hover.py --dur 120

      화면에 "setpoint 스트림 20Hz 발행 시작" 이 뜰 때까지 대기

  [조종사]
      Position 모드로 arm → 수동 이륙 → 고도 2.0 m
      자세가 안정될 때까지 10초 기다림
      ★ 오프보드 스위치 ON

  [SSH 화면 확인]
      위치/속도 소스 = /fmu/out/vehicle_odometry
      nav_state ? → 14  (OFFBOARD)
      ★ OFFBOARD 진입 — 시퀀스 시작
        origin = (...) NED
        yaw0   = ...°
      [   0.1s] HOVER 0/120s
      ...
      ✅ 시퀀스 완료

  [조종사]
      오프보드 OFF → Position 복귀 → 착륙 → disarm
      ★ disarm 확인하고 5초 뒤 전원 분리 (안 그러면 로그가 잘림)

  [SSH]  Ctrl-C

  메모: 로그 파일 시각, 배터리 번호, 체감 풍속


────────────────────────────────────────────────────────────────────────
[3]  ★ F1 로그 확인 — 이걸 해야 F2 를 할 수 있다
────────────────────────────────────────────────────────────────────────
  3-1. FC 를 노트북에 USB 로 연결
  3-2. QGC → Analyze → Log Download → Refresh → 방금 로그 선택 → Download
  3-3. 즉시 이름 변경:  f1_field.ulg
  3-4. 검사:

         python3 check_ulog.py f1_field.ulg --type hover --mass 1.326

  확인할 것:
      · PASS 인가
      · "정지 구간 최장" 이 45초 이상인가
      · "호버 스로틀 u_hover = 0.3xx"   ← ★ 이 값을 적어둘 것
      · "C_thrust = ..." 가 39 N 근처인가 (실내 잠정치 39.5)
      · "GPS 속도 노이즈 σ" 가 0.1 m/s 이하인가 (GPS 정상 신호)

  FAIL 이면:
      · 정지 구간 부족  → 바람이 세거나 스틱 입력이 있었음. F1 재비행
      · C_thrust 가 크게 다름 → AUW 재확인


────────────────────────────────────────────────────────────────────────
[4]  F2 — 자세 doublet   (고도 여유를 최대한 확보)
────────────────────────────────────────────────────────────────────────
  [SSH]   0.3xx 자리에 [3] 에서 얻은 호버 스로틀을 넣는다

      python3 f2_doublet.py --thrust 0.3xx --amp 8 --n 8

      (진입 최소고도 기본 1.5 m — 2.0 m 면 그대로 통과)
      (고도 여유가 더 있으면 --amp 10 이 신호가 더 좋다)

  ★ 2.0 m 에서의 고도 여유 (펄스 0.8초 기준)
        추력이 정확하면        손실 0.03 m
        추력 오차 5%           손실 0.16 m
        추력 오차 10%          손실 0.31 m
      → --thrust 를 [3] 의 실측값으로 넣으면 여유가 충분하다.
        그 값을 대충 넣으면 저고도에서 위험해진다. 반드시 F1 을 먼저 뜰 것.

  [조종사]
      Position 으로 arm → 이륙 → 고도 2.0 m (여유 되면 조금 더 높게)
      안정 후 ★ 오프보드 스위치 ON

  [SSH 화면 확인]
      SETTLE 0/5s ...
      roll 1/8 PULSEA +8°
      roll 1/8 PULSEB -8°
      roll 1/8 RECOVER
      ... (롤 8회) → (피치 8회) → (요 8회)
      ✅ 시퀀스 완료          약 96초 소요

  ★ 중요: 축이 roll → pitch → yaw 순서로 도는지 눈으로 확인.
          섞이면 나중에 계수 분리가 안 된다.

  [조종사] 오프보드 OFF → 착륙 → disarm

  ⚠ 자세 명령 중에는 PX4 가 고도를 안 잡는다. 스크립트가 PD 로 보정하지만
    고도가 눈에 띄게 내려가면 즉시 오프보드를 끄고 인계할 것.

  로그 이름: f2_field.ulg


────────────────────────────────────────────────────────────────────────
[5]  F3 — 직선 왕복 (좁은 공간용 설정)
────────────────────────────────────────────────────────────────────────
  ★ 스위치를 켜기 전에 기수를 "전진시키고 싶은 방향"으로 돌려놓을 것.
    그 방향이 곧 fwd 가 된다.

  필요 공간:  기수 방향 10 m + 기수 기준 오른쪽 10 m
              (origin 뒤쪽·왼쪽으로는 가지 않는다)

  [SSH]
      python3 f3_drag.py --v 2 --leg 4 --pause 2

      시작 시 화면에 비행 범위가 출력된다. 공간과 맞는지 확인할 것.

  [조종사]
      Position 으로 arm → 이륙 → 고도 2.0 m
      ★ 기수를 원하는 전진 방향으로 정렬
      안정 후 ★ 오프보드 스위치 ON

  [SSH 화면 확인]
      SETTLE 0/4s ...
      1/8 fwd+1 CRUISE 0/4s     ← 기수 방향으로 전진
      1/8 fwd+1 PAUSE
      2/8 fwd-1 CRUISE ...      ← 후진
      ...
      5/8 lat+1 CRUISE ...      ← 오른쪽
      ...
      ✅ 시퀀스 완료            약 52초 소요

  [조종사] 오프보드 OFF → 착륙 → disarm

  로그 이름: f3_field.ulg

  여유 되면 속도를 바꿔 한 번 더:
      python3 f3_drag.py --v 3 --leg 4 --pause 2     (공간 12 m 필요)
      → 항력이 속도에 선형인지 교차검증할 수 있다

[6]  철수 전 최종 확인
────────────────────────────────────────────────────────────────────────

      python3 check_ulog.py f1_field.ulg --type hover   --mass 1.326
      python3 check_ulog.py f2_field.ulg --type doublet

      · 축별 "여기 N회" 가 5회 이상인가
      · "롤·피치 동시 여기 비율" 이 15% 미만인가   ← 축 분리의 핵심

  → sim 플랜트 정합 (질량 1.326 + 관성을 G 에 맞춰 스케일)
  → P1 평시 기준선 → P2 밴드


────────────────────────────────────────────────────────────────────────
[8]  문제 발생 시
────────────────────────────────────────────────────────────────────────
  · 오프보드 진입 안 됨 (nav_state 가 14 로 안 바뀜)
      → SSH 화면에 이유가 찍힌다. 보통 고도 부족 또는 위치추정 무효.
      → 더 높이 올리거나, 급하면 --need-alt 0 으로 게이트를 푼다.
      → 기본 진입 최소고도는 1.5 m 다 (저고도 운용 기준).

  · "위치/속도 수신 대기 중" 에서 멈춤
      → 젯슨 ↔ FC 링크 문제. 에이전트 재시작.

  · 시퀀스 도중 ABORT_BOUNDS
      → origin 에서 너무 멀어짐. 공간이 좁으면 --leg 를 줄인다.

  · 언제든 위험하면 조종기로 오프보드 OFF.
      스크립트가 즉시 감지해서 SAFE 로 빠지고 조종사에게 넘어간다.

  5. 로그 3개 회수 → 검사 → 철수

  각 비행 공통:
      arm → 수동 이륙 → 안정 → 오프보드 ON → 완주 → 오프보드 OFF
      → 착륙 → disarm → 5초 후 전원 분리
