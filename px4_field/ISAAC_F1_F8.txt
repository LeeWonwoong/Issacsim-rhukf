              MPC_VEL_MANUAL 이 10 → 2 로 바뀌었으므로 **수동조종 감각 자체가

     G 값을 실기 값과 비교하지 말 것. **보는 것은 거동·경로·안전이다.**

  실기 절차는 RUN.txt.  조종기/QGC 설정은 MANUAL_FLIGHT_SETUP.md.

 1.  나가기 전 — 한 번만 (약 10분)
════════════════════════════════════════════════════════════════════════
  [1-1] 조종기 / QGC Joystick
        MANUAL_FLIGHT_SETUP.md §1~§2 그대로. 요약:
          · 조종기를 USB HID 로 PC 에 연결
          · QGC → Vehicle Setup → Joystick → Enable + Calibrate
          · ★ Button Assignment 에서 버튼 하나를 **Offboard**, 하나를 **Position**
            (QGC 버튼은 토글이 아니라 "누르면 그 모드로 감" 이다)

  [1-2] 잔재 프로세스 — 런처가 검사하지만 미리 치우면 편하다
ros2 topic list | grep gt/odometry        # 아무것도 안 나와야 한다
pgrep -af "run_sim.py|online_rl_main.py|bin/px4"
        나오면:  pkill -f run_sim.py; pkill -9 -f bin/px4   (3초 후 재실행)

  [1-3] uXRCE agent — 런처가 알아서 띄우지만 하나만 떠 있어야 한다
pgrep -x MicroXRCEAgent           # 0개 또는 1개

  [1-4] ★ 제어기 제한값이 실제로 먹었는지
        런처가 부팅 후 `[PX4LIM]` 줄을 화면에 찍어준다. 안 보이면 멈추고
        run_sim.py 의 `_PX4_LIMITS` 를 확인할 것 (run_sim.py:196).
        QGC → Parameters 에서 직접 봐도 된다:
            MPC_XY_VEL_MAX 2.0 / MPC_XY_CRUISE 2.0 / MPC_VEL_MANUAL 2.0

        ⚠ 이 9개는 **폐루프를 바꾼다.** 예전 스윕 결과와 비교 금지.

 2.  기본 실행 형태
════════════════════════════════════════════════════════════════════════
bash px4_field/launch_isaac_manual.sh <f1..f8> [speed] [추가인자...]

  · speed 는 **1.0 고정**. RTF>1 이면 사람 반응이 시뮬 시간 기준으로 느려져
    조종성이 나빠진다. 이 리허설의 목적이 "조종 감각"이므로 1.0 이 아니면 무의미하다.
  · 화면 없는 환경이면  HEADLESS=1 을 앞에 붙인다.
  · Ctrl-C 하면 엔진과 고아 px4 까지 정리한다.

  런처가 하는 일:
    잔재 검사 → MicroXRCEAgent → run_sim.py 백그라운드 → /gt/odometry 로 준비판정
    → [PX4LIM] 확인 출력 → QGC 안내 → 시퀀스 스크립트 포그라운드

  ★ 매 비행 공통 조종 순서 (F2 만 예외)
      arm → **Position 모드**로 수동 이륙 → 고도 안정
      → 기수를 트인 방향으로 → ★오프보드 버튼 ON
      → 스크립트 완주 → Position 버튼으로 인계 → 착륙 → disarm

  감시창 (별도 터미널, 켜두면 좋다)
python3 px4_field/watch_offboard.py --hz 10       # 명령 vs 실제 추종
python3 px4_field/watch_ekf.py --hz 10            # EKF 리셋(★★) 감시
ros2 topic hz /fmu/in/trajectory_setpoint         # 스위치 전엔 조용해야 정상

 3.  F1 — 호버 + (수동) 수직 스윕
════════════════════════════════════════════════════════════════════════
bash px4_field/launch_isaac_manual.sh f1 1.0 --dur 70

  고도 1 m 이상에서 오프보드 진입 가능 (NEED_ALT=1.0, 2026-08-10).

  [조종사]  완주 후 **오프보드만 OFF** → **Position 모드** → 스로틀 스틱을
            위아래로 30초 (고도 0.7~1.5 m 폭, 약 0.5 Hz — 저고도 운용, XY 는 GPS 고정)
            ⚠ 등속 상승은 소용없다. **가속**시켜야 T≠mg 가 된다.

  ✓ 합격 조건
    □ 오프보드 진입 순간 기체가 튀지 않는다 (origin 스냅샷 정상)
    □ 스위치 전에는 /fmu/in/trajectory_setpoint 가 조용하다 (조종기와 안 싸움)
    □ 70초간 제자리를 지킨다 (수평 이탈 1 m 이내)
    □ 인계 후 조종기가 정상 동작한다

  ※ u_hover 는 sim 0.51 근처가 나온다. 실기 0.35 와 다른 게 정상이다
    (추력곡선 모양 불일치. RUN.txt C-3 미결). **비교하지 말 것.**

 4.  F2 — 오토튠            ★ 유일하게 오프보드를 안 쓰는 비행
════════════════════════════════════════════════════════════════════════
  [사전, QGC Parameters]
        MC_AT_EN        = 1     ← 0 이면 모듈이 안 뜬다. **설정 후 재부팅**
        MC_AT_APPLY     = 0     ← ★ 게인 적용 안 함. 기본값 1 이라 반드시 확인
        MC_AT_SYSID_AMP = 1.0

bash px4_field/launch_isaac_manual.sh f2 1.0 --check    # 사전조건만 확인
bash px4_field/launch_isaac_manual.sh f2                # 3초 후 발사

  [조종사]  **Position 모드**로 고도 5 m 이상, 호버 안정.
            ★ 30~40초 동안 롤/피치 스틱에서 **손을 완전히 뗀다.**
            오프보드 버튼은 누르지 않는다 — 오토튠은 PX4 내부 기능이다.

  진행:  ROLL 5.1s → 정지 2.1s → PITCH 5.1s → 정지 → YAW 14.6s → 정지  (총 30~40s)
         기체는 제자리에서 미세하게 떨린다. 크게 안 움직이는 게 정상.

  ✓ 합격 조건
    □ --check 이 통과한다 (MAVLink 연결 · 파라미터 3개 · 스틱 중립)
    □ 30초 이상 후 종료 = 완주.  10초 언저리 종료 = 중단(대개 스틱)
    □ 스틱을 살짝 움직이면 **즉시 중단된다** ← 비상탈출 경로를 여기서 몸에 익힌다

  판독 (참고용. SITL 참값 대조):
~/isaacsim/python.sh px4_field/fit_autotune.py <log>.ulg
    2026-08-06 SITL 실적: roll 157.5(참값 124.9, +26%) / pitch 153.0(157.0, −2.5%)
                          / yaw 86.0(95.2, −9.6%, maxVar 57.7 미수렴)
    → **절차가 참값을 복원한다**는 증명이지 실기 G 와 비교할 값이 아니다.

 5.  F3 — doublet   (+ F3-2 yaw_spin)
════════════════════════════════════════════════════════════════════════
bash px4_field/launch_isaac_manual.sh f3 1.0 --thrust 0.33 --amp 6 --n 1 --settle 3
        ↑ 먼저 확인비행(9초). 고도가 얼마나 빠지는지 본다.
bash px4_field/launch_isaac_manual.sh f3 1.0 --thrust 0.33 --amp 8 --n 8
        ↑ 본비행 96초

  ⚠ F3 은 PX4 가 고도를 안 잡는다(자세각 직접 명령). **2.7 m 이상**에서 시작하고
    조종사는 인계 버튼에 손을 올려둔다.
  ※ --thrust 0.33 은 실기 호버값이다. **sim 에서는 고도가 빠질 수 있다**
    (sim u_hover ≈ 0.51). 리허설이므로 sim 에서만 --thrust 0.50 근처로 올려도 된다.
    ★ 단 실기에서는 0.33 그대로 — 여기서 올린 값을 현장에 가져가지 말 것.

  ✓ 합격 조건
    □ roll → pitch → yaw **순서로** 흔들린다 (눈으로 확인)
    □ doublet 마다 고도가 얼마나 빠지는지 숫자로 확인 (인계 판단 기준이 된다)
    □ ABORT 없이 완주

  ── F3-2  yaw_spin (요축 보조) ─────────────────────────────
bash px4_field/launch_isaac_manual.sh f3b 1.0 --laps 2
        제자리에서 요만 ±90° 정현 왕복. 16초 + settle 4초. **위치 이동 0.**
        오토튠 yaw 가 미수렴(maxVar 53.6)이라 독립 경로로 요축 G 를 본다.
    □ 위치가 안 밀린다 (제자리)
    □ 요가 실제로 ±90° 를 돈다


════════════════════════════════════════════════════════════════════════
 6.  F4 — drag 등속왕복   (+ F4-2 accel_line)
════════════════════════════════════════════════════════════════════════
bash px4_field/launch_isaac_manual.sh f4 1.0 --v 2 --leg 4 --reps 2

  ⚠ --v 2 는 MPC_XY_VEL_MAX 2.0 과 **같다.** 클램프 경계다.
    watch_offboard 에서 실제 속도가 2.0 에 붙어 평평해지면 클램프된 것이다.
    → 그러면 --v 1.75 로 낮춘다 (다른 패턴과 같은 여유 12%).
    ★ 이 판정이 F4 를 sim 에서 먼저 돌리는 가장 큰 이유다.

  [조종사]  기수를 전진 방향으로 돌려놓고 스위치 ON. 왕복 경로 8 m 필요.

  ✓ 합격 조건
    □ position=nan, velocity=값 으로 나간다 (벤치에서 검증 못 하는 경로)
    □ 실제 속도가 2.0 에 클램프되지 않는다
    □ ABORT_BOUNDS 가 안 뜬다 (뜨면 --leg 를 줄인다)

  ── F4-2  accel_line (속도스윕 보조) ───────────────────────
bash px4_field/launch_isaac_manual.sh f4b 1.0 --acc-v 1.75 --laps 2
        기수 방향 직선을 정현 속도로 왕복. v(t)=1.75·sin(2πt/10), 20초 + settle 4초.
        F4 는 단일 속도라 drag 선형성을 못 본다. 이건 속도의 함수로 본다.
        origin 최대이탈 5.6 m (직선).
    □ 속도가 0 ↔ 1.75 를 매끄럽게 훑는다 (클램프 없이)


════════════════════════════════════════════════════════════════════════
 7.  F5 ~ F8 — 기동 패턴          ★ 이번에 처음 나는 것들
════════════════════════════════════════════════════════════════════════
  전부 f5_pattern.py 한 스크립트다. 궤적식은 sim(online_rl_main._compute_setpoint)
  에서 그대로 이식했고, 명령 형식도 같다(TrajectorySetpoint + 속도 FF).

  ── 규격 (sim swrl_config.py 와 **같아야** 비교가 성립) ────────────
        flight_altitude  5.0 m       flight_radius 3.5 m      flight_omega 0.5
        fig8_radius_scale 0.70710678   agg_radius 2.8

    패턴        R/규격             최대속도    T_run(laps 2)  origin 최대이탈
    waypoint    R=3.5              1.75 m/s      24 s           3.0 m
    circle      R=3.5              1.75          25 s           7.0 m  ← 가장 큼
    figure8     R=3.5×0.707=2.47   1.75          25 s           2.5 m
    aggressive  agg_R=2.8          1.76          40 s           2.8 m
                                   ─────────────────────────
                     전 패턴 ≤ 1.76  <  MPC_XY_VEL_MAX 2.0  (여유 12%)

    ★ figure8 의 함정:  x=R sin(ωt), y=(R/2) sin(2ωt) 이면
      vx=Rω cos(ωt), vy=Rω cos(2ωt) 라 **t=0 에서 둘 다 최대** →
      |v|max = R·ω·√2 = 2.47 m/s 로 클램프된다. 그래서 반경만 1/√2 배 했다.
      sim·실기 양쪽 동일 처리. **한쪽만 고치면 비교가 깨진다.**

  [조종사]  고도 **1 m 이상**(NEED_ALT=1.0, 2026-08-10)에서 기수를 트인 방향으로 두고 스위치 ON.
            ⚠ 패턴 수평 공간은 여전히 필요(circle 7×7m). 저고도라도 넓은 곳에서.
            패턴은 오프보드 켠 지점(origin)과 그때의 기수(yaw0)를 기준으로 그려진다.

  ── F5  waypoint ───────────────────────────────────────────
bash px4_field/launch_isaac_manual.sh f5 1.0 --laps 2
        사각 경로 (0,0)→(3.5,0)→(3.5,3.5)→(−3.5,3.5)→(−3.5,0)→(0,0), 등속 1.75 m/s
    □ 코너에서 오버슈트가 얼마인가 (등속 직선 이음이라 코너가 가장 험하다)
    □ yaw 가 진행방향을 따라 도는가

  ── F6  circle ─────────────────────────────────────────────
bash px4_field/launch_isaac_manual.sh f6 1.0 --laps 2
        중심 (−R,0) 이라 t=0 에서 원점을 지난다(시작 갭 제거).
        ★ 기수 뒤쪽으로 7.0 m 를 쓴다 — 네 패턴 중 공간을 가장 많이 먹는다.
    □ 반경이 3.5 m 로 유지되는가 (안쪽으로 말리면 속도 부족)
    □ 접선속도가 1.75 근처인가 (2.0 에 붙으면 클램프)

  ── F7  figure8 ────────────────────────────────────────────
bash px4_field/launch_isaac_manual.sh f7 1.0 --laps 2
    □ 교차점(원점)을 실제로 지나는가
    □ ★ 최대속도가 2.47 이 아니라 1.75 인가  ← 1/√2 보정이 먹었는지 확인

  ── F8  aggressive ─────────────────────────────────────────
bash px4_field/launch_isaac_manual.sh f8 1.0 --laps 1
        4 phase × 5초.  phase0 상승 1.0 m → phase1 반원 → phase2 하강 0.7 m
        → phase3 반원 복귀.  laps 1 = 20초, laps 2 = 40초.
        ★ **고도가 오르내리는 유일한 패턴**이다. 위 0.7 m / 아래 1.0 m 여유 필요.
    □ 수직 진폭이 실제로 ±1.0 / ±0.7 m 인가
    □ 반원 구간 속도 1.76, 수직 0.63 m/s — 클램프 없는가
    □ 급전이(phase 경계)에서 위치오차가 튀는 정도 — 실기 안전판단의 근거

  ⚠ F8 은 실기에서 가장 위험하다. sim 에서 **laps 1 로 먼저** 보고, 궤적이
    납득되면 laps 2 로 늘린다. 현장에서 처음 돌리지 말 것.

 8-2.  ★ ulog 회수 리허설 — fetch_ulog.py 를 SITL 에서 먼저 검증한다
════════════════════════════════════════════════════════════════════════
  실기에서는 이제 QGC 를 안 붙이고 **젯슨이 물고 있는 USB 링크로 바로** 받는다
  (fetch_ulog.py, 2026-08-07 신규). SITL 도 같은 MAVLink 프로토콜이므로
  **여기서 먼저 돌려보고 나가는 게 맞다.** 현장에서 처음 쓰면 안 된다.

  ★ 이건 **자동**이다. 비행 스크립트(f1_hover / f2_doublet / f3_drag / f5_pattern)가
    끝나면 스스로 ① disarm 대기 → ② ulog 회수 → ③ check_ulog 자동 판정 을 한다.
    화면에 "착륙·disarm 을 기다립니다" 가 뜨면 평소대로 착륙하면 된다.

  SITL 에서는 연결을 명시해 주는 게 안전하다:
bash px4_field/launch_isaac_manual.sh f6 1.0 --fetch-conn udpin:0.0.0.0:14540

  ✓ 확인할 것 (여기서 못 보면 현장에서도 못 본다)
    □ 시퀀스 완주 후 "사후처리 — ulog 자동 회수 + 자동 판정" 배너가 뜬다
    □ disarm 하면 곧바로 받기가 시작된다 (진행률·속도·남은시간 표시)
    □ "남은 조각 N개 재요청" 이 몇 번 나와도 **결국 완료**된다 (구멍 메우기 정상)
    □ 파일명에 패턴 이름이 박힌다 →  ulog/f5_circle_log<NN>_<시각>.ulg
    □ 마지막에 판정이 한 줄로 나온다
          ★ 이 소티는 **쓸 수 있다**.      ← PASS
          ★ 이 소티는 **다시 떠야 한다.**  ← FAIL. 위 FAIL 항목이 이유를 말한다
    □ ★ pattern 판정의 "수평속도 클램프" 항목이 OK 인가
      ← 이게 §7 에서 눈으로 보라고 한 것을 **스크립트가 대신 판정한 것**이다

  손으로 하려면:
python3 px4_field/fetch_ulog.py --conn udpin:0.0.0.0:14540 --list
python3 px4_field/fetch_ulog.py --conn udpin:0.0.0.0:14540 --name f6_sitl
python3 px4_field/check_ulog.py ulog/<파일>.ulg --type pattern
  자동 회수를 끄려면 시퀀스에 `--no-fetch` 를 준다.

  ⚠ 워크스테이션에 (다른 장치의) /dev/ttyACM0 이 있으면 자동탐지가 그쪽을 먼저
    고른다. SITL 에서는 `--fetch-conn udpin:0.0.0.0:14540` 을 붙일 것.
  ※ SITL 로그는 원래 ~/PX4-Autopilot/build/px4_sitl_default/rootfs/log/ 에
    그냥 파일로 있다. 여기서 fetch_ulog 를 쓰는 목적은 **파일을 얻는 게 아니라
    현장에서 쓸 경로가 도는지 보는 것**이다.
