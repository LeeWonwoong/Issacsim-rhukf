무엇을 검증하는가
  ★ 오프보드 스위치를 켜기 전에 스크립트가 setpoint 를 발행하지 않는가

  왜 중요한가:
    /fmu/in/trajectory_setpoint 는 PX4 내부의 uORB `trajectory_setpoint` 가
    되는데, **조종기 수동비행의 FlightTask 도 같은 토픽에 발행**한다.
    오프보드가 아닐 때 스크립트가 계속 쓰면 두 발행자가 번갈아 덮어써서
    위치 컨트롤러가 조종기 명령과 스크립트 명령을 교대로 따른다.
    → 호버가 돌고 떨리고 조종기가 안 먹는다  (2026-08-03 실제 발생)

  수정 후 동작:
    스크립트는 조종사가 오프보드를 선택하기 전에는 setpoint 를 안 보낸다.
    (vehicle_status.nav_state_user_intention 으로 스위치 조작을 감지)


────────────────────────────────────────────────────────────────────────
[0]  준비
────────────────────────────────────────────────────────────────────────
  □ 프로펠러 4개 제거
  □ 기체를 테이블에 단단히 고정  (손으로 누르지 말 것)
  □ 최신 코드 복사 확인

      노트북에서:
        cd ~/Downloads && scp -r px4_field <젯슨유저>@<젯슨IP>:~/

      젯슨에서:
        cd ~/px4_field
        grep -c "_may_stream" offboard_common.py      # 4 이상이면 최신
        python3 f1_hover.py --help | grep need-alt    # default: 1.5 면 최신

  □ MPC_THR_HOVER = 50 으로 원복되어 있는지 확인 (QGC)

  ⚠ 프로펠러가 없으면 기체가 자세 명령에 반응하지 못해 자세 컨트롤러
    적분기가 감긴다. 토크 명령이 커지는 것은 정상이다.
  ⚠ 시동 중에는 절대 손대지 말 것. 모터는 돈다.


────────────────────────────────────────────────────────────────────────
[1]  창 두 개를 연다
────────────────────────────────────────────────────────────────────────
  창 1 (스크립트)
      cd ~/px4_field
      python3 f1_hover.py --need-alt 0 --dur 20

  창 2 (★ 핵심 확인)
      ros2 topic hz /fmu/in/trajectory_setpoint --qos-reliability best_effort

  ※ --qos-reliability best_effort 를 빼면 PX4 와 QoS 가 안 맞아
    데이터가 흘러도 아무것도 안 보인다. 반드시 붙일 것.


────────────────────────────────────────────────────────────────────────
[2]  단계별 확인표  — F1 (위치 setpoint 경로)
────────────────────────────────────────────────────────────────────────

  단계                        창 2 (topic hz)      창 1 (스크립트)
  ─────────────────────────────────────────────────────────────────────
  ① 스크립트만 실행           아무것도 안 뜸  ★    "setpoint 는 아직
                                                   발행하지 않습니다"

  ② Stabilized 로 시동        여전히 안 뜸    ★    대기

  ③ 오프보드 스위치 ON        ~10 Hz 시작          "조종사가 오프보드를
                                                   선택함 → 스트림 개방"
                                                   "★ OFFBOARD 진입"
                                                   origin / yaw0 출력

  ④ 시퀀스 진행               10 Hz 유지           HOVER 0/20s ... 20/20s
                                                   "✅ 시퀀스 완료"

  ⑤ 오프보드 스위치 OFF       다시 멈춤       ★    "오프보드 이탈 감지
                                                    → SAFE"

  ⑥ 시동 해제 → 창1 Ctrl-C

  ★ 표시된 세 곳이 핵심이다.
    ①② 에서 창 2 가 조용해야 조종기와 안 싸운다는 증거다.
    ⑤ 에서 다시 멈춰야 인계가 깨끗하다는 증거다.


────────────────────────────────────────────────────────────────────────
[3]  F3 도 확인  (속도 setpoint 경로 — 아직 실기 미검증)
────────────────────────────────────────────────────────────────────────
  창 1:
      python3 f3_drag.py --need-alt 0 --v 0.5 --leg 3 --reps 1 --pause 2

      ※ --v 0.5 로 낮출 것. 3 m/s 를 명령하면 PX4 가 가속하려고
        모터를 세게 돌린다. 경로 검증에는 0.5 로 충분하다.

  창 2: 위와 동일

  확인:
      · [2] 와 같은 패턴 (켜기 전 조용 → 켜면 10 Hz → 끄면 멈춤)
      · 창 1 단계가 fwd+1 → fwd-1 → lat+1 → lat-1 순서로 도는지
      · trajectory_setpoint 내용을 보고 싶으면 창 3 에서:
          ros2 topic echo /fmu/in/trajectory_setpoint \
              --qos-reliability best_effort
        F3 는 position 이 nan 이고 velocity 에 값이 있어야 정상
        (F1 은 반대 — position 에 값, velocity 가 nan)


────────────────────────────────────────────────────────────────────────
[4]  실내라 오프보드 진입이 거부되면
────────────────────────────────────────────────────────────────────────
  실내는 GPS 가 없어 위치 추정이 무효(xy_valid=false)일 수 있다.
  PX4 는 위치 추정 없이는 position 타입 오프보드를 수락하지 않는다.
  창 1 에 이유가 찍힌다.

  그 경우 --bench 를 붙인다:
      python3 f1_hover.py --bench --dur 20
      python3 f2_doublet.py --bench --n 2 --settle 2

  ⚠ --bench 는 위치·속도 명령을 **자세 명령으로 대체**한다.
    따라서 창 2 에서 봐야 할 토픽이 바뀐다:
        ros2 topic hz /fmu/in/vehicle_attitude_setpoint \
            --qos-reliability best_effort

  ⚠ --bench 로는 위치/속도 setpoint 경로가 검증되지 않는다.
    그건 실외에서 확인해야 한다.


────────────────────────────────────────────────────────────────────────
[5]  통과 기준
────────────────────────────────────────────────────────────────────────
  □ 스위치 켜기 전 창 2 가 조용하다              ← 가장 중요
  □ 스위치 ON 하면 창 1 이 "OFFBOARD 진입" 출력
  □ 시퀀스가 끝까지 돌고 "✅ 시퀀스 완료"
  □ 스위치 OFF 하면 창 2 가 멈추고 창 1 이 "SAFE"
  □ F1, F3 둘 다 위 패턴

  전부 통과하면 실비행(FIELD_PROCEDURE.txt) 으로 진행한다.


────────────────────────────────────────────────────────────────────────
[6]  실패했을 때
────────────────────────────────────────────────────────────────────────
  · 창 2 가 스위치 전부터 값이 뜬다
      → 구 버전 코드다. [0] 의 복사·확인을 다시 할 것.

  · 창 2 가 스위치를 켜도 아무것도 안 뜬다
      → --qos-reliability best_effort 를 빼먹었는지 확인
      → 그래도 없으면 창 1 에 오프보드 진입 거부 사유가 있는지 볼 것

  · 창 1 이 "위치/속도 수신 대기 중" 에서 멈춤
      → 젯슨 ↔ FC 링크 문제. 에이전트 확인:
          ros2 topic echo /fmu/out/vehicle_status \
              --qos-reliability best_effort --once

  · 창 1 이 "위치 추정 무효" 로 거부
      → 실내라 정상. [4] 의 --bench 로.

  · 스크립트가 죽음
      → 트레이스백 전체를 기록해 둘 것.
