  실기 로그 분석은 전부 --mass 1.342 을 쓴다.
  반영 완료: FIELD_PROCEDURE.txt / RUN.txt / check_ulog.py / fit_from_ulog.py
             CLAUDE.md / HANDOFF_FIELD_20260804.md

  ⚠ 남은 것 — **sim 플랜트는 아직 1.372 kg 이다.**
      run_sim._apply_body_calib · calibration/calibration.json ·
      C_thrust 25.58 · 관성 (0.029547, 0.026484, 0.053359)
      이 전부 1.372 기준으로 맞춰져 있다. 이 값들을 지금 손으로 고치지 않는다 —
      실기 F1/F2/F3 계수(C_thrust, G, drag)가 나오면 그걸로 한 번에 재정합한다.
      (FIELD_PROCEDURE [7], RUN.txt [5])

  왜 중요한가 — C_thrust 에 1차로 그대로 들어간다:

      C_thrust  =  m·g / u_hover        (호버 평형, 선형 secant)

      예)  m=1.342 → 13.17 N / 0.33 ≈ 39.9      ← FIELD_PROCEDURE 의 기대치
           m=1.372 → 13.46 N / 0.33 ≈ 40.8

    질량이 3.5% 틀리면 C_thrust 가 그대로 3.5% 틀린다. 이건 F1 의 유일한 산출물이고,
    그 값이 F2·F3 와 sim 플랜트 정합까지 전부 타고 내려간다.

[B]  ✅ 완료 — FC 파라미터 3줄, QGC 반영 + 재부팅 (2026-08-04)
════════════════════════════════════════════════════════════════════════

  ── 적용한 것 ──────────────────────────────────────────────

      UAVCAN_SUB_FLOW    0 → 1     ARK Flow(노드 125) 옵티컬 플로우 구독
      UAVCAN_SUB_RNG     0 → 1     AFBR-S50 거리센서 구독
      EKF2_HGT_REF       2 → 1     고도 기준 = **GPS**  (2=거리센서, 1=GPS)

  ── EKF2_HGT_REF 를 왜 같이 바꿨나 ─────────────────────────

    6호기는 EKF2_HGT_REF=2 (거리센서 기준)인데 UAVCAN_SUB_RNG=0 이라
    거리 데이터가 하나도 안 들어온다. 즉 **없는 소스를 고도 기준으로 지정해 둔**
    상태였고, 그래서 지금까지 무해했다.

    UAVCAN_SUB_RNG=1 하는 순간 이 설정이 처음으로 발효된다.
    "UAVCAN 만 켜고 나머지는 안 건드린다" 가 성립하지 않는 이유다.

    실외에서 거리센서 기준이면:
      · 고도 기준이 지면 추종이 된다 → 풀·둔덕·경사에서 EKF 고도가 지형을
        따라가고, 위치제어기가 그만큼 기체를 올렸다 내렸다 한다.
        F1/F2/F3 데이터가 오염된다.
      · EKF2_RNG_CTRL=1(조건부) + RNG_A_HMAX=5 + RNG_A_VMAX=1 이라
        5 m 이하 & 1 m/s 이하에서만 붙는데, 그 경계를 넘나들 때마다
        고도 기준이 갈아탄다 — 튀기 딱 좋은 구간.

    HGT_REF=1 로 두면 거리센서는 고도 "기준"이 아니라 저고도 "보조"로만 쓰이고
    플로우 스케일링에는 그대로 쓰인다. 원하는 이득은 다 가져간다.

  ── 일부러 안 바꾸는 것 ────────────────────────────────────

    7호기(1.17.0)와 6호기(1.15.4-dev)의 EKF2_/UAVCAN_ 차이는 13개다.
    그중 위 3개만 쓴다. 나머지 이유:

      EKF2_GPS_CTRL     7호기 0 / 6호기 7   ★ 가져오면 안 됨. 7호기는 실내
                                             전용이라 GPS 융합을 꺼둔 것.
                                             옮기면 실외 비행 불가.
      EKF2_RNG_A_HMAX   7호기 10 / 6호기 5   6호기 값이 더 보수적. 실외 직사광
                                             에서 AFBR-S50 유효거리가 짧아지므로
                                             5 유지가 맞다.
      EKF2_RNG_QLTY_T   7호기 0.2 / 6호기 1  6호기 값이 더 보수적(수용까지 1초
                                             연속 양호 요구). 실외 지면 품질이
                                             들쭉날쭉하므로 1.0 유지가 맞다.
      EKF2_OF_POS_Z     0 유지               레버암 2 cm. ω=1 rad/s 에서 속도
      EKF2_RNG_POS_Z    0 유지               오차 0.02 m/s, 고도 상수 2 cm. 무시 가능
      EKF2_OF_DELAY     20 유지              5 ms 차이. 1 m/s 에서 5 mm. 무시 가능
      EKF2_DECL_TYPE / EKF2_IMU_CTRL         자기편각·IMU 바이어스. 플로우 무관
      EKF2_TAS_GATE / EKF2_WIND_NSD          고정익 대기속도용. 멀티콥터 무관

    7호기에만 있는 EKF2_OF_GYR_SRC / EKF2_RNG_FOG / UAVCAN_RNG_MIN/MAX 는
    6호기 펌웨어에 존재하지 않는다. 옮길 수 없고, 없어도 융합된다.
    SENS_FLOW_* 도 6호기 comp1 에는 아예 없다(전수 확인). 노드(comp 125) 쪽은
    두 기체 모두 100/8/scale 1.0 으로 이미 동일하다.

  ※ PX4_6_sensor_patch.params (8줄) 은 "실내/실외 겸용" 안이었다.
    실외 전용으로 가기로 했으므로 위 3줄만 쓴다. 파일은 이력으로 남겨둔다.

  ※ MPC_THR_HOVER 는 건드리지 않는다 (0.5 유지). FIELD_PROCEDURE [1-4] 참조.

[D]  젯슨에 수정된 코드 업로드
════════════════════════════════════════════════════════════════════════

  ── 올릴 것 ────────────────────────────────────────────────

    젯슨에서 실행되는 것만 올리면 된다:

        offboard_common.py     ★ 공통 모듈 — 최근 수정됨. 이것만 빠지면 전부 실패
        f1_hover.py
        f2_doublet.py
        f3_drag.py
        watch_offboard.py      두 번째 SSH 창에서 관찰용

    분석 스크립트(check_ulog.py, fit_from_ulog.py)는 **노트북에 둔다.**
    pyulog 만 있으면 되고 ROS2 가 필요 없다. 젯슨에 올려도 무방.

  ── 방법 1 : rsync   (젯슨과 같은 네트워크일 때 — 이쪽이 간단) ──

rsync -av --exclude='__pycache__' --exclude='firmware' --exclude='field_logs' --exclude='*.csv' --exclude='*.ulg' --exclude='*.params' ~/projects/Issacsim-rhukf/px4_field/ <젯슨유저>@<젯슨IP>:~/px4_field/

    ⚠ --delete 는 넣지 않았다. 젯슨에만 있는 파일(예전 현장 로그)을 지우지
      않기 위해서다. 완전히 동일하게 맞추고 싶을 때만 붙인다.

  ── 방법 2 : USB   (SSH 가 안 될 때) ───────────────────────

    워크스테이션에서:

tar czf /media/$USER/<USB>/px4_field.tgz --exclude=__pycache__ --exclude=firmware --exclude=field_logs -C ~/projects/Issacsim-rhukf px4_field

sync && udisksctl unmount -b /dev/sdX1

    젯슨에서:

tar xzf /media/<...>/px4_field.tgz -C ~

    → ~/px4_field/ 로 풀린다.

  ── 업로드 후 젯슨에서 검증 (여기까지 해야 D 가 끝난다) ────

    (1) 묵은 바이트코드 제거 — 구버전 .pyc 가 남아 있으면 수정이 반영 안 된다

rm -rf ~/px4_field/__pycache__

    (2) ROS2 환경 + 임포트 스모크 테스트

source /opt/ros/humble/setup.bash

cd ~/px4_field && python3 f1_hover.py --help

        → 도움말이 뜨면 rclpy · px4_msgs · offboard_common 임포트까지 전부 정상.
          여기서 나는 에러는 현장이 아니라 지금 잡아야 한다.
          (px4_msgs 를 못 찾으면 px4_msgs 워크스페이스의 install/setup.bash 도
           source 해야 한다)

    (3) 도메인 ID 확인 — FC 의 UXRCE_DDS_DOM_ID=0 과 맞아야 한다

echo "[$ROS_DOMAIN_ID]"

        → [] (빈 값 = 0) 또는 [0] 이어야 한다. 다른 값이면 토픽이 안 보인다.

    (4) 에이전트 띄우고 토픽 확인 (FC 와 연결된 상태에서)

MicroXRCEAgent serial --dev /dev/ttyUSB0 -b 921600

        다른 창에서:

ros2 topic echo /fmu/out/vehicle_status --qos-reliability best_effort --once

        → 한 줄 찍히면 젯슨↔FC 링크 정상. 현장 [1-3] 이 이걸로 대체된다.

  ── 지금 6호기가 DDS 펌웨어인가? ───────────────────────────

    정황: PX4_6.params 헤더가 `Version: 1.15.4 dev` — "dev" 는 로컬 빌드 표시다
          (4호기는 `1.15.0`, 릴리스 표기). 이미 플래시돼 있을 가능성이 높다.

    ⚠ 다만 git 해시로는 판정할 수 없다. yaml 변경은 git 해시에 안 들어간다
      (REAL_AIRFRAME_DDS_SETUP.txt [8]). QGC 콘솔의 `listener` 로도 판정 못 한다

    확실한 판정은 ROS2 쪽에서만 가능하다 ([D]-(4) 상태에서):

ros2 topic list | grep -E "thrust_setpoint|torque_setpoint"

      나오면    → 이미 DDS 펌웨어. 할 일 없음.
      안 나오면 → 표준 펌웨어. **그래도 이번 현장은 그대로 나간다.**
                  플래시는 RL 배포 전에 하면 된다.
                  (절차는 REAL_AIRFRAME_DDS_SETUP.txt [T]→[4])
