## 1. 실기체 ↔ Isaac Sim ↔ UKF 정합

### 1-1. 센서 노이즈 — sim은 이미 실기 수준 (이식 불필요)
| | sim 측정 | 실기 실측 | 판정 |
|---|---|---|---|
| gyro σ [x,y,z] | [0.089, 0.080, 0.028] | [0.072~0.134, 0.069~0.116, 0.023~0.032] | ✓ 일치 |
| GPS vel σ [E,N,U] | [0.078, 0.084, 0.073] | [0.11, 0.09, 0.17~0.33] | ~ 수평OK, 수직 낮음 |

- gyro는 PX4 SITL이 실기 수준으로 생성. GPS 수직만 2~4배 낮으나 roll/pitch(수평) 공격엔 무관.

### 1-2. 플랜트 구조 (Isaac) vs UKF 모델
```
Isaac 플랜트: QuadraticThrustCurve(T∝ω², THR_MDL_FAC=0.78) + MOTOR_TAU=0.014s(14ms 지연) + LinearDrag[0.5,0.3,0]
UKF:          선형 C_thrust·C_torque + 모터지연 없음 + 선형 drag (= 단순화 강체모델)
```
- **자연 모델오차 존재**: gyro innovation res_g=0.239 = 센서노이즈(0.154) ⊕ 모델오차(~0.18 rad/s).
- 단 **기동 의존 아님** (aggressive res_g 0.239 = hover 0.239): 속도 낮아 모터지연(14ms<20ms스텝)·2차추력 비선형이 정착·가려짐.

## 2. 공격 모델 & 밴드

### 2-1. 주입 구조 (불변)
- PX4 `ControlAllocator::apply_attack()` 의 `c[0]`(배분 직전 정규화 wrench)에 additive δ 가산. sim=실기 동일 코드.
- **불변식**: δ는 UKF가 u로 읽는 `torque/thrust_setpoint` **하류** → UKF가 못 보고 잔차로 드러남.
- ★ `ATK_EN=1` 누락 버그 수정(2026-08-13) — 그 전 모든 headless 스윕은 무공격이었음.

### 2-2. 결과성 밴드 (축당 δ = 정규화 권한비, thrust=0)
| δ(축당) | 판정 | roll각 | 근거 |
|---|---|---|---|
| 0.40~0.70 | **하이재킹** (표류·미추락) | 16~32° | track 표류 0.6→4m, dhover 억제 0.02~0.05m |
| ~0.80 | **추락+호버구제** (crash_drift) | 50~60° | track 추락 / dhover d≤5 생존 1.0 |
| ≥0.85 | **flip** (구제불가) | 63°+ | dhover도 전멸 |

- **단일축(roll/pitch) = 결합(틸트) 문턱 동일**(축당 0.85 flip). 결합은 표류 2배·방향자유.
- roll ≈ pitch 대칭. yaw 단독 = 위치 하이재킹 아님(회전만, 표류≈0).
- **전 5궤적 유지**. 샘플러: 틸트크기 m∈[0.4,0.8] 랜덤방향, 축당<0.83 클램프.

### 2-3. 공격 형태 — 상수 vs FDI 펄스 (on/off)
| | 상수 bias | 무작위 펄스 γ_k·b (표준 FDI) |
|---|---|---|
| 결과성 | worst-case(밴드 정의) | 약함(δ0.7 표류 8.7→1.0m, OFF구간 회복) |
| gyro d′ (탐지) | 4~6.5 (threshold/CUSUM 충분) | 단일 1.1 → **윈도우 1.6 (+45%)** |
| 논문 역할 | 밴드 정의 baseline | **기여 무대** (윈도우·RHUKF-FV 필요) |

→ **펄스가 본실험**(sparse 샘플효율·RL>CUSUM). 상수는 밴드 정의용.

### 2-4. ★프레이밍 결정 (2026-08-18) — FDI + "궤적 이탈"
- **공격 = 표준 FDI**: `a_k = γ_k · b_k` (지시함수 γ_k on/off × bias b_k 크기). **학습 시 γ_k(버스트 타이밍)·b_k(밴드 내 크기) 둘 다 랜덤**. 특성화 실험만 한 축 고정(측정용).
- **결과성 프레이밍 = (B) "궤적 이탈"** (NOT (A) 표적 하이재킹):
  - 공격 = 적대적 제어입력 교란이 드론을 **의도 궤적에서 밀어냄**. 정밀 표적제어 주장 안 함(PX4가 싸워 불가).
  - 방어 = 호버 = **오염된 미션 실행 거부·안전위치 유지** (앞 "호버=명령거부"와 정합).
- **★결과성 임계값 하향**: (A)는 8m 하이재킹 필요(→큰 δ→자명탐지). **(B)는 안전임계 이탈**(정밀미션·장애물·지오펜스서 **~1~2m 이탈=안전위반**).
  - → **중간/펄스 공격(이탈 1m)이 "결과적(안전위반) ∧ 회피적(gyro d′ 1.2→2.6, 윈도우필요)" 둘 다 성립** → 딜레마 완화.
- **딜레마 정리**: "결과성⟹자명탐지"는 (A)+상수 한정. **(B)+FDI펄스**면 결과성(안전이탈)·회피성(윈도우) 양립.

## 5. 왜 평시 NIS/innovation이 낮은가 (closed-loop 분석)

**세 요인 중첩:**
1. **모델 잘 정합** (sim2real 결과) → 자연 모델오차 ~0.18, 기동 의존 약함.
2. **속도 낮음** (실기 안전캡) → 모터지연·비선형 덜 드러남.
3. **R 큼 (고집 설계)** → NIS로 보면 더 눌림 (raw innovation은 반응, ★NIS만 보면 오판).

**바람 (closed-loop 감도함수 S=1/(1+L)):**
- 위치 채널: PX4 적분기가 정상 추종 유지 → 약풍서 위치 잔차 ≈0 ("정상처럼 난다").
- 속도 채널: 잔차 ∝ 바람력/질량. 약풍<노이즈바닥 → 묻힘. **강풍(ws9~) → 드러남**(nis_v 0.52).
- 주파수: DC/저주파 바람 억제(S≈0, wind_constant 폐기), 고주파 난류 통과(S≈1).

**결론**: 결과적 공격(δ≥0.4)은 강해 쉽게 탐지 / benign aliasing은 **잘-정합·저속·고집 sim에선 약함**. **단 강풍(9+)은 예외** — 다음 절.

## 6. Perceptual Aliasing POMDP — 바람 & 슬라이딩 윈도우

### 6-1. 확립된 aliasing 원천
- **펄스 간헐성** (주): 공격 OFF 간격 샘플 = 평시처럼 보임 → 단일관측 애매, **윈도우가 해소(+45% d′)**. 이 sim에서 작동하는 유일·깨끗한 POMDP.
- **강풍** (신규, ws9 확인): PX4 보상 넘겨 드론 밀림(0.77m/s) → **vel innovation 2.8×, nis_v 7.4×**. vel 채널 aliasing.

### 6-2. 강풍 하한선 & 윈도우 효과 — ⏳ 밤샘 스윕 진행 중
```
turbulence 5~15 정밀 + gust 5/9/15, 전궤적, 시간창(바람80~220·공격140~260), 속도1×
측정: nis_v가 노이즈 넘는 하한 wind speed / gust vs turbulence / 공격vs바람 d′ 단일vs윈도우
```
- **가설(수식 예측)**: turbulence(광대역)가 gust(저주파 단발)보다 지속 innovation. 윈도우가 vel 채널 aliasing 해소.
- **결과 (① windthreshold 완료 2026-08-18)**:

  1. **강풍 하한선 ≈ ws7~9** — turbulence 9부터 nis_v가 baseline(0.08) 초과. ws12~15 강한 aliasing.

### 6-3. ★윈도우/RL 정당화 최종 (딜레마 해소)
```
              gyro d′ 단일 → 윈도우
 상수/지속:    6.5 → 6.5    threshold 충분(불변식 강점, 재미없음)
 FDI 펄스:     1.2 → 2.6    ★단일 비자명(OFF간격=평시) → 윈도우/RL 필수
```
- 탐지 쉬운 건 **상수/지속** 한정. **FDI 펄스**가 RL/윈도우가 threshold·CUSUM 이기는 자리.
- (B) 프레이밍(이탈 ~1m=안전위반)으로 펄스도 **결과적 ∧ 회피적** 양립.

### 6-4. ★기여의 본질 — 복귀 결정 (양방향 stopping under POMDP)
FDI 펄스에 호버로 대응하면 **OFF 간격마다 복귀 결정**이 남는다. 이게 RL의 자리:
- **복귀(track)** = 미션 재개(이득) but 다음 버스트 리스크(표류)
- **호버 유지** = 안전 but 미션시간 낭비(**denial 비용**)
- **★POMDP**: OFF간격이 "캠페인 중 일시 공백"인지 "공격 종료"인지 **단일 NIS로 모름**(둘 다 NIS≈평시). 최근 윈도우로 "방금 버스트 있었나" 추론 → 캠페인 진행중이면 호버 유지, 오래 낮으면 복귀.
- **threshold/CUSUM**: 매 OFF간격 즉시 복귀 → 다음 버스트에 당함(플리커). **RL**: 윈도우로 캠페인 추론 → 비용최적 복귀 타이밍.

**펄스 = lose-lose 강제**: track→표류(안전위반) / hover→미션거부(denial). 방어자는 **총비용(표류+denial) 최소화**. 공격은 어느 쪽이든 비용 강제 = 성공.
- **∴ RL이 threshold 이기는 지점 = 탐지가 아니라 "복귀 결정"의 비자명성.** 실기 방어자의 실제 딜레마.
- 보상 구현: OFF간격 hover=FP(미션손실=denial비용), ON버스트 track=FN(표류). **FP/FN 비율 + OFF간격 분포**가 flicker↔commit 균형 결정(튜닝축).

## 7. 종합 결론 & 다음

**프레임워크 확정 (2026-08-18):**
1. **공격**: 표준 FDI `a_k=γ_k·b_k`. (B) "궤적 이탈" 프레이밍 — 결과성=안전임계 이탈(~1m), 방어=호버(오염미션 거부). 밴드 축당 δ0.4~0.8, flip≥0.85, 전궤적·방향 무관.
2. **탐지**: 주입 불변식으로 gyro가 지속공격을 자명 탐지(강점). **어떤 모델오차·바람으로도 gyro aliasing 안 생김**(③ 확인). 바람은 vel만 가림, gyro 강건.
3. **RL/윈도우 정당화 = FDI 펄스**: gyro 단일 d′ 1.2(OFF간격=평시) → 윈도우 2.6. threshold/CUSUM은 펄스서 실패(플리커/누적리셋), 윈도우 RL은 캠페인 커밋. (B)로 펄스도 결과적.
4. **Q·R** = gyro R0.2/Q5e-3, vel R0.1 (적용). 복귀 ~0.1s(양방향 stopping).
5. **환경**: turbulence(nominal 0.5 / aliasing 9~15), gust 폐기. 커플링 유지.
